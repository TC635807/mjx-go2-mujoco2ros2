# 仿真保真度 / 信号链排查记录（2026-10-20）

用户在观察器里看到的现象：帧率极低（RTF 0.31，约 5 fps）+ 机器人抽搐/行动诡异 +
地形上走不动/摔倒 + 窗口跑到一半自己消失。本文件记录逐项定位、修复与验证数据，
以及**仍未解决**的仿真器接触语义问题。

## 1. 帧率：三处开销（已修复，RTF 0.31 -> 0.99~1.0）

| # | 开销 | 实测 | 修复 |
|---|---|---|---|
| 1 | 策略前向默认 OpenBLAS 多线程（1024-512 小矩阵） | **11.97 ms/次**（50 Hz => 600 ms/s，且占满 12~16 核） | 入口脚本 setdefault OPENBLAS/OMP/MKL = 1；**0.21 ms/次** |
| 2 | 激光 raycast：3000 条射线 Python 逐条 mj_ray，50 Hz | **28 ms/帧** => 1.4 s/s | 改 `mj_multiRay` 批量投射 + `perception.rate_hz=15` + 默认 900 射线：**~5.2 ms/帧 * 15 Hz** |
| 3 | 500 Hz 循环里每步做 read_state + 健康 + 安全（~0.5 ms/步） | ~25% 实时预算 | 观察器按 `--monitor-hz 100` 分频，物理仍 500 Hz；安全层 dt 同步放大 |
| 4 | 内嵌 matplotlib 面板（无 Qt 时）全图重绘 | 仪表盘单帧 45~80 ms | 面板单帧耗时预算 `--panel-budget-ms 25`，超预算自动降刷新率 |

修复后：headless `rtf 1.0+`、GUI `rtf 0.999`；`lag_p95_ms` 从 22321 降到 2.7~6.2。

复现命令：

    bash scripts/view_go2_policy.sh --terrain hyb2        # GUI
    bash scripts/view_go2_policy.sh --headless --duration 10   # 无 GUI

## 2. 观测信号 bug（root cause，已修复）

`ros2_controller/obs.py::projected_gravity` 把 R 的**第三列** (R02/R12/R22) 当成了
**第三行** (R20/R21/R22) 来算 `R^T @ [0,0,-1]`。纯 yaw 时两者都等于 [0,0,-1]，
所以平地/直行几乎看不出来；但**一旦有 roll/pitch，重力 xy 的符号是反的**，
策略等于拿到了反号的倾角反馈 —— 这正是"抽搐/诡异"的直接来源。

证据（`scripts/verify_train_deploy_obs.py`，训练侧 eval_go2 为参考）：

| 状态 | 修复前 max\|diff\| | 修复后 |
|---|---|---|
| home 静止（无 roll/pitch） | 0 | 0 |
| 随机姿态 + 速度（roll/pitch 0.34 rad） | **0.627**（obs[6:9]） | **0** |
| yaw 90° + 侧向指令 | 0 | 0 |

修复后 243 维 obs **逐段 max|diff| = 0**（0:3 线速度 / 3:6 角速度 / 6:9 重力 /
9:12 指令 / 12:24 关节位置 / 24:36 关节速度 / 36:48 last_action / 48:235 高度扫描 /
235:243 相位），12 维动作 jax(pkl) vs numpy(npz) **max|diff| <= 1.15e-6**。

回归测试已加入 `tests/test_obs.py`（200 个随机四元数 + 侧倾 11.5° 显式断言）。

## 3. "两层网络 + 不归一化"是否导致单位敏感？

v25b 是 1024-512（2 个隐层）tanh，输出 loc（normal 分布）。训练时
`normalize_observations=False`，但观测是**手工缩放**的（v*2.0 / w*0.25 /
cmd*2.0 / height_scan*5.0，再 clip ±100），部署侧逐项复刻同一套缩放 ——
所以"没归一化"本身不是问题，问题是**缩放/符号/坐标系必须逐位一致**，
而上面那个 bug 正好破坏了一处。现在有对账脚本把这个契约钉死了。

动作全部落在关节限幅内/外也不是 bug：训练侧 `target 顶到范围边界的比例 = 28%`，
`目标被限幅的步占比 = 100%`（CPU 参考评测同样如此），部署 `n_action_clamped=100%`
与训练口径一致。

## 4. CPU MuJoCo hfield 接触语义与 MJX warp 不一致 —— **已修复（2026-10-21）**

### 4.1 根因（已确认）

CPU MuJoCo 里一个球体 vs hfield 会返回 **6 个重复接触点**（plane 只有 1 个）；
同一策略、同一起点、同一代码：

| 地面 | 6 s 前进距离 |
|---|---|
| scene_flat.xml（plane） | **2.17 m** |
| 纯平 hfield（elevation 全 0） | **0.54 m** |
| hfield 场景去掉 hfield、只留 box + plane | **1.68 m** |

训练用 MJX warp 后端不是这个接触语义，所以**训练出来的策略在 CPU hfield 地形上会
抽搐/走不动，而在 plane 平地上完全正常** —— 这与用户观察完全一致。

### 4.2 修复：hfield 只做视觉，碰撞换成倾斜 box 瓦片

改 `mjx-go2-training/sim/export_deploy_terrains.py`：

1. 用 CPU MuJoCo 对训练场景的 hfield 表面做 raycast 采样（0.2 m 网格；只取"命中 hfield
   且非平坦"的格点 + 其邻域，平坦区域交给 plane 兜底）；
2. 每个格点生成一个倾斜 box 碰撞瓦片（法向由高度梯度得到，厚 0.12 m，隐藏 `rgba=...0`）；
3. hfield 保留为**视觉 geom**（`contype=0 conaffinity=0 group=3`），不再参与碰撞；
4. 追加一个 `floor_plane`（比视觉面低 2 mm）给平坦区域兜底。

于是 CPU 侧每次足-地接触回到 **1 个接触点**（与 plane 同语义），而视觉、高度扫描
（raycast）仍然是原来的 hfield 表面。

### 4.3 修复后实测（同策略、同起点、同 spawn 序列）

| 地形 | 修复前 | 修复后 | 训练侧 warp 评测 |
|---|---|---|---|
| hyb2（24 seeds, 6 s） | 50.0%（12 seeds） | **66.7%**，v=0.236 m/s，tilt_max=19.1° | 86.7% |
| rubble（12 seeds） | 15 s 只走 0.6 m | **75.0%**，v=0.255 m/s | 80.7% |
| big1（12 seeds） | 15 s 只走 1.7 m | **75.0%**，v=0.230 m/s | 80.0% |
| hyb2 外圈出生 6 s 前进 | 0.55 m | **1.46 m**（平地参照 2.17 m） | — |

物理成本没有变差：碰撞瓦片 599~2578 个时 `mj_step` 仍是 **0.05~0.08 ms**
（原 hfield 场景 0.17 ms），500 Hz 无压力。

剩余与 warp 的差距（66.7% vs 86.7%）来自**另一个轴**：CPU Newton（hard contact 100/50）
vs MJX warp（hard contact 20/10、naconmax 等）的求解器差异，不是本次接触几何 bug。

## 5. 第二轮修复（2026-10-21 晚）：瓦片缝"卡死" + raycast 可见性 + 视觉 hfield group

用户反馈（turn 60）: "经常发生脚卡到地面里后完全动不了", 怀疑"楔在瓦片竖缝/台阶立面";
要求注意性能损耗。诊断由 Agent Team 完成（T1 卡死力学取证 + T2 碰撞表示 A/B,
报告见 /tmp/t1_wedge/report.md 与 /tmp/t2_coll/report.md, 脚本
scripts/stuck_forensics.py 与 scripts/collision_bench.py）。

### 5.1 根因（T1 接触取证: v25b, 16 seeds × 15s, ring 出生）

严格卡死判据: 连续 >=1.2s 基座平面位移 <2cm（cmd=0.4、tilt<30°、未摔倒、过 2.5s
warmup）; 缝夹(pinch)判据: 同一足球同时有 2 个接触、世界法向水平分量 |n_xy|>0.7 且
对立、两侧法向力均 >30N。

| 地形 | 摔倒 | 非出生期严格卡死 | 缝夹 seeds | 缝夹 s/seed | 前进 m |
|---|---|---|---|---|---|
| flat | 0/16 | 0 | 0/16 | 0 | 4.84 |
| hyb2 | 0/16 | **2**（~0.5 事件/min） | **6/16** | 1.04 | 4.03（−17%） |
| stg1 | 2/16 | 0 | 3/16 | 1.54 | 3.34（−31%） |

逐例接触证据：3/3 非出生期严格卡死 = **球足被两块相邻倾斜碰撞瓦片的近竖直侧面
夹在缝里** —— 持续穿透 2.1–2.5cm、单接触法向力 0.67–0.74kN（整足 1.3–1.7kN，
正常站立约 40N/足）、被卡足 xy 位移 <=8mm、逃逸后数值弹射 5m。另有 1 例是小腿/
机身顶在 0.22m 真竖面台阶上（不是球足被楔）。

合成最小实验（2kg 足型球 r=22mm 落接缝中点，98/56 落点）：精确尺寸瓦片
**52%(合成)/79%(真实 hyb2 瓦片区)** 落点持续嵌入；瓦片 xy ×1.02→9–16%；**×1.05→0%**；
连续三角面→0%。→ 根因 = **精确尺寸瓦片在接缝处留下比足球窄的缝**（旧注释
"精确尺寸更好"是混淆变量，已被受控 A/B 推翻）。

附带发现（T2）：CPU MuJoCo 3.12 的 mj_ray **完全跳过 rgba alpha==0 的 geom** →
旧场景隐藏瓦片对 raycast 不可见；而视觉 hfield 是 group=3（与机器人碰撞同组），
被环境组掩码排除 → 用环境组掩码的 raycast（出生点地面探测等）只能打到 floor_plane：
uniform 出生四足嵌进地形 2–8cm（mean −22.3mm，37.5%>2cm）→ 6/16 假卡死、前进 −54%。
（perception 的 height_scan 因 self_occlusion 时 mask=None，仍能看到 hfield，故观察器
里的扫描一直是好的；坏的是出生探测/评测这类用 group 掩码的 raycast。）

### 5.2 修复（sim/export_deploy_terrains.py）

1. **碰撞瓦片 xy 尺寸 ×1.05（每边重叠 5mm）**：只改 size，瓦片数量/位置/厚度/
   性能完全不变（ngeom 793、ncon 22、mj_step 0.07–0.10ms、45.4MB 与现状逐项相同）。
   缝贯穿率 7.27%（缝深 28mm）→ **0.26%**（10mm）；严格卡死中的瓦缝型事件消失。
2. **瓦片 alpha 保持 0（对 raycast 隐形）**：若改 alpha=0.01 让扫描看到"碰撞包络"，
   策略 tilt_p95 从 11.5° 升到 17.6°、hyb2 存活 75%→66.7% —— 扫描应看"视觉地形面"
   而不是碰撞近似面（重叠产生的凸棱/抬高 1–2cm 是表示误差，不属于真实地形）。
3. **视觉 hfield group 3→1**：环境组掩码 raycast 可见 → 出生点地面探测与
   height_scan 都打到训练同款高度面（视觉 hfield = 训练 hfield），出生嵌入问题消除。
4. 评测出生高度改为四足偏移点下方地形最高点 +2cm（scripts/eval_terrain_matrix.py）。

### 5.10 地形视觉统一 + 观察器帧率修复 (2026-10-22, 用户反馈)

**用户反馈**: ① 地形外观不一致: 有些突起是棕色, 有些和地面同色; 有的高度能看出有的看不出,
但都有碰撞; ② 观察器帧率低、相邻画面间隔长。

**根因 (读导出模板/场景实测)**:
* 部署场景里 **两套可视几何** 并存: hfield 视觉面用 `groundplane` 材质 (地面色), 而 box 地形
  的方块从训练场景原样复制, 带 `box_mat`/`wall_mat` 棕色材质 -> 同一个地形里两种颜色;
* hfield 地形 (hyb*/mix/stairs_only/...) 的起伏是"地面色"的 hfield 视觉面, 只有明暗没有颜色区分,
  所以高度难辨认; box 地形又是棕色方块 -> 用户看到的"有的能识别有的不能";
* 物理碰撞由 **不可见的倾斜瓦片 (alpha=0)** 或 box geom 承担, 所以"看不出高度但也有碰撞"
  是符合设计的 (视觉面 vs 碰撞近似面), 但两套视觉几何并存让观感很乱;
* 帧率: big1 场景 **3168 个 geom** 全部参与渲染 (2044 个 alpha=0 瓦片 + 1071 个 box),
  在 WSLg/llvmpipe 软件渲染下每帧都要遍历/提交这些几何 -> 帧率极低; 此外 viewer 左右 UI 也在渲染。

**修复 (训练仓 `sim/export_deploy_terrains.py` + 部署仓 `scripts/view_policy.py`)**:
1. **统一材质**: 所有地形表面 (hfield / 方块 / 台阶) 共用同一个 `groundplane` 材质
   (暖灰 checker + 网格线 `mark=edge`, texrepeat 10x10); 训练场景 box 行复制时去掉
   棕色 `material/rgba`, 统一改成 `groundplane`;
2. **碰撞几何隐藏渲染**: box geom、倾斜碰撞瓦片、floor_plane 全部放进 `group=4`; 观察器默认
   `viewer.opt.geomgroup[4]=0` (机器人碰撞几何 group=3 也隐藏) -> 渲染只剩"地面 hfield +
   1 个视觉地形网格";
3. **box 地形生成视觉网格 OBJ**: 从 boxgrid 高度表生成顶面+竖面的 mesh
   (`assets/terrain_<name>_vis.obj`, 一个 geom), 保留台阶/箱体的清晰竖面和高度;
   hfield 地形仍用 hfield 视觉面; 两者材质统一 -> 所有地形外观一致、高度可辨;
4. **物理/感知完全不变**: hfield group=1 (ray 可见)、box/瓦片 alpha 与 group 只影响渲染,
   raycast/height_scan 仍命中碰撞几何 (smoke 实测 hyb2: height_scan_mean=-0.103, hit_rate 0.619);
5. **帧率**: 渲染可见 geom 数: big1 **3168 -> 35**, hyb2 **794 -> 35**, mix **2009 -> 34**,
   stairs_only **2342 -> 34**, wide_h050 **477 -> 35**; viewer 关闭左右侧 UI; 另新增
   `--robot-style lite` (隐藏机器人高模网格, 只显示碰撞几何, 软件渲染 fps 优先)。

验证: 31 个地形全部重导出; `tests/test_terrain_scenes.py` 契约更新 (box/瓦片 group=4、
视觉网格存在) -> **12/12 测试通过**; headless 观察器 hyb2 4s 实测 rtf=1.0、upright、
感知链路正常。

### 5.11 观察器扫描点"碰到障碍物消失"的诊断与修复 (2026-10-22)

**用户反馈**: 画面里地面上的点点是雷达高度扫描点; 碰到障碍物时点不随障碍物升高而是消失,
怀疑模型输入高度有问题。

**诊断结论: 模型输入没有问题, 问题在观察器的"真值显示"射线。**

1. **两套东西要分清**:
   * 观察器 3D 画面里的小球 = `sim_env/viz/frame.py::RaycastGround` —— 从 (x,y,2m) 垂直
     向下 raycast 得到的**地面真值**, 只用于观察/对照;
   * 策略实际输入 = `signal_io/perception.py::SimLidar` (点云) -> `HeightMapper` (稀疏高程图)
     -> 187 维 height_scan (与训练口径一致)。
2. **模型输入实测正确** (新增 `scripts/probe_height_scan_ground_truth.py`):
   wide_h050 楼梯口, 187 点中直接观测 88 个, 观测点上 |h_map - h_true| **mean 0.009 m / max 0.05 m**;
   第一级台阶处 h_map=0.050 (真值 0.050), 0.10m 台阶上 scan 特征 -0.24/-0.28 (负=上坡, 与训练
   定义一致) —— 感知链路能看到障碍物并正确抬高;
3. **根因**: v33 视觉统一把碰撞 box 从 group0 移到 **group4**, 但 RaycastGround 的旧 mask 是
   `(1,0,0,0,0,0)` (只看 group1) -> 射线在障碍物处直接打到下面的地面, 点被障碍物网格挡住,
   看起来就是"碰到障碍物就消失"; 之前 box 在 group0 所以没暴露。

**修复**:
* `RaycastGround` 默认 mask 改为 `(1,1,0,0,1,0)` (group1 视觉 hfield/网格 + group4 碰撞 box/瓦片);
* 采样点抬高 6mm, 避免小球与台面 z-fighting 被遮挡;
* 同步修正 `scripts/collision_bench.py` 与 `tests/test_terrain_scenes.py` 里的硬编码 mask;
* 新增回归测试: RaycastGround 必须看到 group4, 且 wide_h050 台阶处高度 = 0.05/0.30。

**验证**: RaycastGround 在 wide_h050 沿 x 的 [入口, 0.05 台阶, 0.10 台阶, 0.15, 平台] 返回
`[0.000, 0.050, 0.100, 0.150, 0.300]`; 测试 12/12 通过 (含新回归测试)。
